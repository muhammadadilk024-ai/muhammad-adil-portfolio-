# muhammadadil.cloud: AI friendly SEO audit, plan and rebuild

Date: 2026-10-12. Method: Beyond SEO skill, Apify Intelligence Mode (Google SERP actor, 13 queries, Canada),
direct crawl and crawler user agent tests, Google Search Console (owner account), Lighthouse 12.8 on a local build
(the Hostinger CDN returns 403 to headless Chrome, so the public PageSpeed API could not be used; the keyless API
quota was also exhausted that day).

## 1. Executive summary

The old site was a single page React app with good metadata and a crawler fallback, but it had no URL architecture
(one indexable URL, plus a stray `www` duplicate), no answer content, no entity proof links, no AI assistant file,
two AI crawlers blocked by the CDN, and a mobile page 15,760 px tall (19 screens) dominated by text. It scored
**40/100** on the AI friendly SEO model.

The site was rebuilt as nine prerendered pages (home, projects, three case studies, services, about, contact,
privacy) with a single identity source, a complete JSON-LD graph, visible FAQs mirrored in FAQPage schema,
`llms.txt`, a canonical host redirect, a branded 404, a new design system (Manrope, one accent, flat warm black)
and no animation library. Local Lighthouse: performance 98 to 100, accessibility 100, best practices 100, SEO 100
on every page. Estimated score after the rebuild: **78/100**. The remaining points depend on things only external
signals can give: third party mentions, reviews, backlinks and time in the index.

## 4. Strategy

1. **Entity first.** One identity source, Person + Organization graph with sameAs (LinkedIn, GitHub, Aatox), About
   page as a ProfilePage, consistent facts everywhere (name, Canada, Tech Joint Solution Calgary since 2024, founder of
   Aatox 2026, building since 2021, 20+ client projects).
2. **One URL per intent.** Projects hub, three case study pages, services, about, contact. Each page has one title,
   one H1, one description, breadcrumbs and its own schema.
3. **Answer content.** Visible FAQs (hiring questions on home, buying questions on services) mirrored in FAQPage
   schema; direct answer blocks (challenge, what I built, flow, notes) on case studies.
4. **Source worthiness for AI.** Prerendered HTML (no JavaScript needed), `llms.txt`, explicit robots allowances for
   AI crawlers, factual claims only, live links as proof, dates.
5. **Conversion.** One primary action (start a conversation), risk reversal (free first call, your hosting, your
   code), proof next to claims, validated form, direct lines.
6. **Design for reading on a phone.** Shorter sections, cards instead of walls of text, one typeface, no heavy
   effects, reveals with IntersectionObserver.

## 5. What was built

- Vite multi page build with `scripts/prerender.mjs` (React server render into each HTML entry).
- Pages: `/`, `/projects/`, `/projects/knowwhere/`, `/projects/bc-scrap-cars/`, `/projects/sb-traworld/`,
  `/services/`, `/about/`, `/contact/`, `/privacy/` (noindex), `404.html`.
- Head per page: title, description, canonical, robots, Open Graph, Twitter card, JSON-LD graph.
- Schema: Person (sameAs, worksFor, knowsAbout), Organization (Tech Joint Solution, Aatox with founder), WebSite,
  ProfilePage (home, about), ProfessionalService with OfferCatalog (home, services), FAQPage (home, services),
  CollectionPage + ItemList (projects), BreadcrumbList (all sub pages), SoftwareApplication (KnowWhere).
- `public/llms.txt`, `public/robots.txt` naming AI crawlers, `public/sitemap.xml` with 8 URLs and lastmod,
  `public/.htaccess` (www to apex 301, http to https, `index.html` to `/`, 404 document, cache headers).
- New social image (1200x630 JPEG, 83 KB), new icons, portrait converted to WebP (61 KB and 26 KB).
- Design: Manrope self hosted (two woff2 subsets, 40 KB), warm black `#131209`, cream text, one amber accent
  `#e9a066`, Phosphor icons inlined, floating island navigation, full screen mobile menu with staggered links,
  hero heading gradient, tagline reveal section, scroll reveals, custom easing, hover, active and focus states.
- Removed: framer-motion (about 100 KB), intro loader, blur glow layers, marquee ribbons, carousel, unused images
  (about 2 MB), two unused components.
- Contact form: visible labels, inline validation on blur, specific error text, success state, honeypot.

## 7. 30 / 60 / 90 day plan

### Days 1 to 30 (technical and entity)

- Deploy (done), resubmit the sitemap in GSC and request indexing for every new URL (done on deploy day).
- Owner: in hPanel set the CDN security level to "Low" (or "Essentially off") so GPTBot and meta-externalagent
  get 200; re-test with `curl -A GPTBot/1.0 -o /dev/null -w "%{http_code}" https://muhammadadil.cloud/`.
- Owner: add the site to Bing Webmaster Tools (import from Search Console) and submit the sitemap.
- Add the portfolio URL to every profile that allows one: LinkedIn (done), GitHub profile README and bio, the
  Aatox About page (sameAs back to muhammadadil.cloud), Tech Joint Solution team page if the agency has one.
- Collect two or three real client quotes (WhatsApp screenshots or written permission) for a testimonials block.

### Days 31 to 60 (proof and content)

- Publish one dated article per month on the site under `/writing/` (for example "How I structured 12 city pages
  for local SEO in Laravel", "Keeping an API key off a Flutter app with a Cloudflare Worker"). Each links to the
  matching case study and the services page.
- Republish each article on dev.to and LinkedIn Articles with a canonical link back to the site (entity and
  third party mentions).
- Ask Tech Joint Solution for a developer profile or a mention on their site, and ask two clients for a "built by"
  footer link where appropriate.
- Add a `/testimonials/` section once quotes exist, with Review schema only for genuine, attributable quotes.

### Days 61 to 90 (authority and monitoring)

- Monthly checks: GSC impressions and clicks for branded queries, indexed page count, Bing AI Performance report,
  and the same 13 SERP queries through Apify for comparison.
- Answer two or three relevant questions on Reddit, Stack Overflow or Laravel and Flutter communities with the case
  studies as references (no link dropping).
- Review the Google Knowledge Panel situation: once sameAs links and third party mentions are consistent, request a
  panel claim if one appears.
